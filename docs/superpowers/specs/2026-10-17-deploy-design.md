# 设计：云服务域名证书部署与更新（`sslbear-cli deploy`）

2026-10-17

## 为什么做

sslbear-cli 现在只能查询：列出 6 家云、21 个服务上的域名和各自绑定的证书。用户要的是让使用云服务的开发者，**通过 AI（Claude Code、Cursor 这类 agent）调用 `npx sslbear-cli`**，把手上已有的证书部署到云上的域名，或把快到期的旧证书换成新的。要尽快可用。

证书从哪来不在本次范围：假设使用者已经有证书和私钥（PEM 文件）。

## 目标

- 一条命令完成「部署」和「更新」：传入证书 + 私钥，CLI 找出证书覆盖的云上域名，按规则部署或替换。
- 主要调用方是 AI：参数一次传完、不弹交互确认；`--json` 结果能让 agent 判断每个域名发生了什么、失败能否重试；重复执行是安全的。
- 覆盖现有查询支持的全部 6 家云、21 个服务（见 README「命令」一节的服务表）。

## 不做

- 证书的申请、签发、续签（ACME 等）。
- 删除或吊销云上的旧证书，不清理证书服务里的历史证书。
- 修改 HTTPS 以外的域名配置（回源、缓存、HTTP/2、HSTS、TLS 版本、强制跳转等都不碰）。
- 部署到 CLB / SLB / WAF 等负载均衡、防护类产品（现有查询也不覆盖）。

## 绝不能发生（反目标）

- 把一张证书换到它不覆盖的域名上（会导致证书错误）。
- 在用户定的规则之外替换证书：**当前证书还有 30 天以上才到期的，一律不替换**。
- 把一个没开 HTTPS 的域名悄悄开成 HTTPS（未经 `--domain` 点名）。
- 私钥出现在任何输出、日志、错误信息里。
- 用新证书替换掉一张到期时间更晚的证书（降级）。

## 用户已定的规则

1. **更新**（域名已经绑了证书）：只有当前证书 **30 天内到期（含已过期）** 才替换，否则跳过，并在结果里写明「当前证书还剩 N 天，未到更新时间」。阈值 30 天固定，不提供参数放宽（我的判断：用户把它当作安全边界，agent 拿到放宽参数就会用）。
2. **部署**（域名没有证书 / 没开 HTTPS）：用户没有额外限制。按与用户确认过的方案：没开 HTTPS 的域名默认不动，只有用 `--domain` 精确点名时才部署并开启 HTTPS。

## 命令

```
sslbear-cli deploy --cert <fullchain.pem> --key <privkey.pem> [选项]
  --cert <path>            证书文件（PEM，叶子证书 + 中间证书链）
  --key <path>             私钥文件（PEM，RSA 或 ECC，不支持加密私钥）
  -p, --provider <list>    只处理指定云厂商；默认为所有已配置凭证的云厂商
  -s, --service <list>     只处理指定服务（与 domains 的取值相同）
  -d, --domain <list>      只处理这些域名（精确匹配，逗号分隔，可重复）；点名的域名没开 HTTPS 时会部署并开启
      --dry-run            只输出计划，不做任何写操作（也不上传证书）
      --timeout <ms>       单个请求超时，默认 15000
      --json               输出单行 JSON
      --env-file <path>    从指定文件加载环境变量
```

注意 `deploy` 的 `-d` 是**精确匹配的域名列表**，与 `domains` 命令里 `-d` 的关键字过滤语义不同（我的判断：写操作不能用模糊匹配圈定范围）。

## 执行流程

1. **校验本地证书**（任一不通过 → 参数错误，exit 2，不调用任何云接口）：
   - 证书与私钥能解析，且私钥与证书公钥匹配。
   - 证书文件包含中间证书链（只有一张非自签叶子证书时拒绝，提示用 fullchain）。我的判断：缺链的证书部署上去会让部分客户端握手失败，宁可拒绝让 agent 修正。
   - 证书当前在有效期内。
   - 从证书取出覆盖的域名：SAN 里的 DNS 名（没有 SAN 时取 CN）。
2. **查询现状**：复用 `domains` 的查询逻辑，拿到所选云/服务上的全部域名及当前证书。查询失败的服务记入 `issues`，其中的域名无法处理。
3. **匹配域名**：云上域名被新证书覆盖才纳入，覆盖规则同浏览器：精确匹配，或 `*.example.com` 覆盖一级子域（不覆盖 `example.com` 本身，也不覆盖多级）。云上的泛域名（`*.example.com`，七牛写作 `.example.com`）只能由含同样泛域名的证书覆盖。`--domain` 点名但证书不覆盖、或在所选云/服务上找不到的域名，记为失败并说明原因（不是静默忽略）。
4. **逐个域名决策**（按顺序，第一条命中即定）。下表的「旧证书」指新证书将要替换掉的那张：开着 HTTPS 的域名是当前证书；没开 HTTPS 但服务上仍绑着证书（bound-off）的是那张仍绑着的证书；什么都没绑就没有旧证书，第 4~7 行不适用。

   | # | 情况 | 动作（`reason`） |
   | --- | --- | --- |
   | 1 | 平台托管域名（`extra.managed: "platform"`） | 跳过（`platform_managed`） |
   | 2 | 该服务不支持通过 API 部署，或尚未通过真实账号验收（见「交付顺序」） | 跳过（`unsupported`） |
   | 3 | 没开 HTTPS，且未被 `--domain` 点名 | 跳过（`https_off`），提示需用 --domain 点名 |
   | 4 | 旧证书是云厂商自动续期的托管证书（**待确认，见文末问题 1**） | 跳过（`auto_renew`） |
   | 5 | 查不到旧证书的到期时间 | 跳过（`unknown_expiry`） |
   | 6 | 旧证书到期时间 ≥ 新证书到期时间 | 跳过（`already_current`） |
   | 7 | 旧证书剩余 > 30 天 | 跳过（`not_due`），说明剩 N 天 |
   | 8 | 没开 HTTPS（已被点名） | **部署**并开启 HTTPS（`deployed`） |
   | 9 | 其余（旧证书剩余 ≤ 30 天或已过期） | **更新**为新证书（`updated`） |

   - 「同一张证书」用到期时间判断（第 6 行），所以重复执行会自然跳过已完成的域名。到期时间比较允许各云的时间精度误差（有的服务只精确到天），具体容差由实现决定。
   - 30 天规则和防降级对点名的 bound-off 域名同样生效：仍绑着的证书剩 30 天以上时跳过，也不开启 HTTPS（我的判断：用户的 30 天规则是「一律」）。
   - **双证书**（RSA + ECC 双证书，华为的国际 + 国密）：只替换与新证书同算法的那张，决策按那张的到期时间；域名上只有另一算法的证书时，把它当作旧证书。国密证书永远不动。另一张证书原样保留（我的判断：不能悄悄删掉用户的另一张证书；重复执行时同算法那张已是新证书，第 6 行跳过）。查询层需要能拿到每个域名的全部证书，而不只是最早到期的那张。
   - **阿里云 ESA 普通记录**：证书挂在站点上，往站点上传一张证书会作用到站点下所有被它覆盖的记录，所以按站点整体判断：站点下被新证书覆盖、且开着 HTTPS 的记录必须**全部**会走到第 9 行（若用了 `--domain`，还必须全部被点名），才往站点上传证书；否则这些记录都跳过（`shared_cert_blocked`），`message` 写明是哪条记录挡住了。没开 HTTPS 的 ESA 记录即使被点名也不处理（`unsupported`），因为开启 HTTPS 要改站点的 SSL/TLS 规则，影响面超出单个域名。ESA 的 SaaS 域名证书在域名自身上，按上表逐个处理。（我的判断，依据是「剩 30 天以上一律不替换」和「未点名不动」两条反目标。）
5. **执行**（非 `--dry-run`）：
   - 需要证书 ID 才能绑定的服务，先把证书上传到该云的证书服务，同一次运行内每家云只传一次；证书服务里已有同一张证书（同指纹或同序列号）时复用，不重复上传。上传后的证书名带域名和到期日，便于在 `certs` 里认出来（命名格式实现时定）。
   - 能直接接收 PEM 的服务可以直接传 PEM，是否仍先上传到证书服务由实现决定（倾向于统一走证书服务，便于复用和在控制台查看）。
   - 只修改 HTTPS 证书相关的配置，其他配置保持原样；对「整体覆盖式」的配置接口，必须先读出原配置再只改证书字段。
   - 云接口受理即算成功，不等待边缘节点生效（各云生效需要几秒到几分钟）；结果里提示用 `domains` 稍后核对。
   - 同一云内适度并发，遵守各云限流（如七牛 10 QPS），可重试的错误（限流、网络超时）按现有 `withRetry` 重试。
6. **输出结果**。

## 输出契约

沿用现有约定（meedu-cli 风格）：成功时 stdout 一行 `{"ok":true,"data":...}`；失败时 stderr 一行 `{"ok":false,"status","message",...}`。

```json
{"ok":true,"data":{
  "dryRun":false,
  "cert":{"commonName":"example.com","sans":["example.com","*.example.com"],"notAfter":"2027-01-15T00:00:00.000Z","fingerprint":"sha256:..."},
  "uploads":[{"provider":"aliyun","certId":"12345","reused":false}],
  "results":[
    {"provider":"aliyun","service":"cdn","domain":"static.example.com","action":"updated",
     "before":{"name":"old","notAfter":"2026-11-02T10:00:00.000Z","daysLeft":16},
     "after":{"id":"12345","notAfter":"2027-01-15T00:00:00.000Z"}},
    {"provider":"tencent","service":"cdn","domain":"www.example.com","action":"skipped","reason":"not_due","message":"当前证书还剩 75 天，未到更新时间"},
    {"provider":"aliyun","service":"oss","domain":"img.example.com","action":"failed","code":"Forbidden","message":"...","requestId":"...","retryable":false}
  ],
  "issues":[]
}}
```

- `action`：`deployed`（原先没开 HTTPS）、`updated`（替换旧证书）、`skipped`、`failed`；`--dry-run` 时为 `would_deploy` / `would_update` / `skipped` / `failed`（failed 仅限点名域名不存在、不覆盖这类本地可判定的问题）。
- `reason`（跳过原因的稳定枚举，供 agent 判断）：`platform_managed`、`unsupported`、`https_off`、`auto_renew`、`unknown_expiry`、`already_current`、`not_due`、`shared_cert_blocked`；`message` 为中文说明。
- `retryable`：失败是否值得原样重试（限流、超时、网络错误为 true；鉴权、权限、参数错误为 false）。
- 退出码：
  - `0`：没有任何 `failed`（全部成功或跳过，包括「什么都没改」）。
  - `1`：至少一个域名失败，或所有查询都失败。stderr 输出 `{"ok":false,"status":"DeployFailed","message":"…","results":[…],"uploads":[…],"issues":[…]}`，完整结果仍可解析。
  - `2`：参数、证书文件或凭证配置错误（未调用任何写接口）。
- 表格模式：每个域名一行（云厂商 / 服务 / 域名 / 动作 / 说明），最后一行汇总「更新 N、部署 N、跳过 N、失败 N」。

## 安全

- 私钥只在内存里读取并发给云接口，不写盘、不打印；错误信息里出现请求体时要剔除私钥。
- 写操作需要各云的写权限，README「所需权限」补充 deploy 所需的最小权限（各服务的域名配置写权限 + 证书服务上传权限）。README 开头「只读」的说法改为：`domains` / `certs` / `env` 只读，`deploy` 会修改配置。

## 交付顺序

用户希望尽快可用，分两批交付，每批都要用真实账号验收后再推送：

1. 阿里云（CDN、DCDN、ESA、OSS、直播、点播）+ 腾讯云（CDN、EdgeOne、COS、直播、点播）。
2. 火山引擎、华为云、百度智能云、七牛云。

某个服务的 API 无法安全地只替换证书（或根本不支持）时，该服务记为 `unsupported` 并在 README「已知限制」说明，不阻塞整批交付。

测试环境里无法真实验收的服务（腾讯云 EdgeOne 没有 0 元套餐未开通；火山引擎 veImageX 服务审核中）的处理见文末问题 2。

每批验收通过后的发布方式见文末问题 3。

## 验收

- 单元测试：证书解析与覆盖匹配（含泛域名、七牛的 `.example.com` 写法）、决策表每一行、输出契约与退出码、各服务写接口的请求构造（mock）。
- 真实账号：复用 `../sslbear-e2e` 环境（测试域名 `*.sslbear-test.luoxuan.xyz`，各服务已有 on / off / bound-off 三类测试域名，`setup/*-lib.ts` 里已有各云绑定证书的写接口封装可参考）。
  - 只允许改测试域名，执行时必须用 `-d` 限定到 `*.sslbear-test.luoxuan.xyz` 下的域名；账号里其他域名（`*.dev.sslbear.com`、`*.meedu.xyz`、`*.playedu.xyz`）绝对不能动。
  - 需要验证的路径：未到期跳过（现有测试证书 2027-01-15 到期，正好覆盖）、30 天内到期的更新（需要一张短有效期证书，如 Let's Encrypt 的 shortlived 证书，先部署它再用常规证书更新）、点名部署到 off 域名、重复执行全部跳过、`--dry-run` 不产生写操作。
  - 部署后用 `domains` 和 `tlscheck.mjs` 核对边缘实际下发的证书。

## 留给实现的

- 每个服务具体用哪个写接口、是否先上传证书服务、如何开启 HTTPS（参考各云文档与 sslbear-e2e 的 setup 脚本；腾讯云 SSL 的 `DeployCertificateInstance`、阿里云 CAS 的部署任务这类统一部署接口可以考虑，但要确认它们满足「只改证书」和同步返回结果）。
- 到期时间比较的容差、证书服务里的命名格式、并发度。
- 代码结构：在 `DomainService` 上加可选的部署能力，或另建注册表，按现有代码风格决定。

## 待用户确认的问题（附推荐做法）

1. **旧证书是云厂商自动续期的免费 / 托管证书时，到了 30 天窗口要不要替换？**（阿里云 CDN 的免费证书、ESA 免费证书、腾讯云 EdgeOne 免费证书、华为云 CDN 托管证书）替换后这个域名就从「云厂商自动续期」变成「用户自己续期」。
   推荐：**不替换**，跳过并标 `auto_renew`。这类证书通常在到期前自动续上，落进 30 天窗口多半只是续期还没执行。
2. **测试环境里无法真实验收的服务怎么上线？**（腾讯云 EdgeOne、火山引擎 veImageX）
   推荐：**先标 `unsupported`**（提示「尚未验证」），等能用真实账号验收后再放开。写操作会直接改用户的线上配置，只靠 mock 测试风险太大。
3. **每批验收通过后是否直接发 npm 新版本？**
   推荐：第一批完成后升到 **0.2.0**，第二批 **0.3.0**；推送 tag 后 CI 暂存发布，你在 npmjs.com 批准后用户就能 `npx sslbear-cli deploy` 用上。

## 我的判断（请顺带过目）

- 30 天阈值固定，不提供放宽参数。
- 缺中间证书链的证书直接拒绝。
- `deploy -d` 是精确域名列表，不是关键字过滤。
- 点名的 bound-off 域名同样受 30 天规则约束。
- 双证书只替换同算法那张，国密证书不动。
- ESA 普通记录按站点整体判断，没开 HTTPS 的 ESA 记录不处理。
- 云接口受理即算成功，不等待边缘节点生效。
- 有任何域名失败就 exit 1，完整结果仍在 stderr 的 JSON 里。
