# deploy 命令（证书部署与更新）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增 `sslbear-cli deploy --cert --key`：把本地证书部署 / 更新到 6 家云、21 个服务上被它覆盖的域名，规则见设计文档。

**Architecture:** 新增 `src/deploy/`（本地证书解析、覆盖匹配、决策、执行编排），复用现有 `queryDomains` 拿现状；每个 `DomainService` 增加可选的 `deployer`，每个 `ProviderDef` 增加可选的 `uploadCertificate`。编排层按决策表产出计划，`--dry-run` 只出计划，否则按服务调用 deployer 并汇总结果。

**Tech Stack:** TypeScript、Node ≥ 18.17（`node:crypto` 的 `X509Certificate` / `createPrivateKey`）、commander、vitest；零运行时依赖。

**Spec:** `docs/superpowers/specs/2026-10-17-deploy-design.md`

## Global Constraints

- 零运行时依赖；签名用现有手写实现，不引 SDK。
- 输出契约：`--json` 成功 stdout 单行 `{"ok":true,"data"}`；失败 stderr 单行 `{"ok":false,status,message,...}`；exit 0 / 1（有域名失败或全部查询失败）/ 2（参数、证书文件、凭证错误）。
- 30 天阈值固定：`RENEW_WITHIN_DAYS = 30`，不提供参数。
- 「同一张证书」容差：两张证书 notAfter 相差 ≤ 48 小时（`SAME_CERT_TOLERANCE_MS = 172_800_000`）视为同一张；旧证书比新证书晚超过 48 小时为 `newer_current`。
- 私钥不得出现在任何 stdout / stderr / 错误信息里。
- 只改 HTTPS 证书相关配置；整体覆盖式接口必须先读后改。
- 测试与真实账号验收时只能动 `*.sslbear-test.luoxuan.xyz`；`*.dev.sslbear.com`、`*.meedu.xyz`、`*.playedu.xyz` 绝不能动。
- 测试里不放云厂商文档的示例密钥原文（GitHub Push Protection 会拦）。

## Review Focus

1. 证书文件里中间证书在前、叶子在后，或带 `\r\n`、BOM、多余空行 —— 应能正确找出叶子证书（与私钥匹配的那张），不误判缺链。
2. 云上域名大小写不同、带结尾点、七牛泛域名写作 `.example.com` —— 应与证书 SAN 正确匹配；`*.example.com` 不覆盖 `example.com` 和 `a.b.example.com`。
3. 一个服务查询失败（issues）而 `-d` 点名的域名恰好在那个服务上 —— 应记为 failed 并在 message 里提示该服务查询失败，而不是「找不到域名」了事。
4. 写接口超时后自动重试 —— 上传证书不能因此在证书服务里传出两份（上传前先查重，重试走同一查重逻辑）。
5. 云接口报错信息里回显了请求参数 —— 输出前要把私钥 PEM 内容替换掉。

### Task 1: 本地证书解析与覆盖匹配

**Files:** Create `src/deploy/cert.ts`、`test/deploy-cert.test.ts`、`test/fixtures/deploy/*`（用 openssl 生成：测试 CA；叶子 RSA 与 ECC，SAN = `example.com, *.example.com`，有效期 2026-01-01 至 2027-01-01；`fullchain-*.pem` = 叶子 + CA；`leaf-only.pem`；`other-key.pem` 与叶子不匹配；`chain-reversed.pem` = CA 在前）。

**Interfaces — Produces:**

```ts
export interface LocalCert {
  certPem: string;        // 叶子在前、中间证书在后，规范化为 \n 结尾
  keyPem: string;
  commonName?: string;
  sans: string[];         // 小写 DNS 名；无 SAN 时取 CN
  notBefore: string;      // ISO
  notAfter: string;       // ISO
  algorithm: "RSA" | "ECC";
  fingerprint: string;    // 叶子 DER 的 sha256，小写 hex 无冒号
  serialNumber: string;   // 大写 hex
  issuer?: string;
}
export function loadLocalCert(certPem: string, keyPem: string, now: Date): LocalCert; // 不合格抛 UsageError
export function normalizeDomain(d: string): string;   // 小写、去结尾点、".a.com" → "*.a.com"
export function certCovers(sans: string[], domain: string): boolean;
```

- [ ] Step 1：写测试 —— RSA/ECC fullchain 解析出 sans `["example.com","*.example.com"]`、algorithm、notAfter `2027-01-01T…Z`；`chain-reversed` 仍以叶子为准且 `certPem` 叶子在前；`leaf-only` 抛 UsageError（文案含「中间证书」「fullchain」）；`other-key` 抛「私钥与证书不匹配」；now 在有效期外抛「不在有效期内」；加密私钥 / 非 PEM 抛 UsageError；`certCovers` 覆盖 `example.com`、`A.Example.com.`、`.example.com`→`*.example.com`（仅当 SAN 含 `*.example.com`），不覆盖 `a.b.example.com`、`example.org`。
- [ ] Step 2：`npx vitest run test/deploy-cert.test.ts` 失败。
- [ ] Step 3：实现。叶子 = 公钥与私钥匹配（`X509Certificate.checkPrivateKey`）的那张；缺链判定 = 只有一张且不是自签（`issuer !== subject`）；SAN 从 `subjectAltName` 解析 `DNS:` 项。
- [ ] Step 4：测试通过。
- [ ] Step 5：commit `feat(deploy): 本地证书解析与域名覆盖匹配`。

export type SkipReason = "platform_managed" | "unsupported" | "https_off" | "already_current"

export const NEEDS_CONFIRM: ReadonlySet<SkipReason>; // unknown_expiry / newer_current / not_due

  message?: string;

### Task 3: 部署接口与编排

**Files:** Modify `src/providers/registry.ts`、`src/lib/http.ts`；Create `src/deploy/run.ts`、`test/deploy-run.test.ts`。

**Interfaces — Produces（Task 5–10 依赖）:**

```ts
// registry.ts
export interface DeployTarget {
  /** 通常 1 条；sharedScope 相同的记录合并为一组（如 ESA 同一站点） */
  records: DomainRecord[];
  mode: "deploy" | "update";
}
export interface DeployInput {
  cert: LocalCert;
  /** 上传到本云证书服务并返回证书 ID：每次运行每家云最多上传一次，已存在则复用 */
  certId(): Promise<string>;
}
export interface DeployOutcome { certId?: string; note?: string }
export interface Deployer<C> {
  /** 记录级限制，返回不支持的原因（中文）；如推流域名不能绑证书、该服务不能经 API 开启 HTTPS */
  unsupported?(record: DomainRecord, mode: "deploy" | "update"): string | undefined;
  /** 证书挂在共享对象上时返回其键 */
  sharedScope?(record: DomainRecord): string | undefined;
  apply(ctx: QueryContext, creds: C, target: DeployTarget, input: DeployInput): Promise<DeployOutcome>;
}
// DomainService<C> 增加：deployer?: Deployer<C>   —— 未定义即整个服务 unsupported
// ProviderDef<C> 增加：uploadCertificate?(ctx: QueryContext, creds: C, cert: LocalCert): Promise<{ id: string; reused: boolean }>
// http.ts
export function isRetryable(e: unknown): boolean; // withRetry 改用它
// run.ts
export interface DeployOptions { providers?: Provider[]; services?: string[]; domains?: string[]; force: boolean; dryRun: boolean }
export interface DeployResult {
  provider: Provider; service: string; domain: string;
  action: "deployed" | "updated" | "would_deploy" | "would_update" | "skipped" | "failed";
  reason?: SkipReason; message?: string; needsConfirm?: true;
  before?: CertInfo & { daysLeft?: number }; after?: { id?: string; notAfter: string };
  code?: string; requestId?: string; retryable?: boolean;
}
export interface DeployReport {
  dryRun: boolean;
  cert: Pick<LocalCert, "commonName" | "sans" | "notAfter" | "algorithm" | "fingerprint">;
  uploads: { provider: Provider; certId: string; reused: boolean }[];
  results: DeployResult[];
  issues: QueryIssue[];
  succeeded: number; // 查询成功数，沿用 emit 的「全部查询失败」判定
}
export function planDeploy(ctx: QueryContext, cert: LocalCert, opts: DeployOptions, defs?: Record<Provider, ProviderDef<any>>): Promise<{ report: DeployReport; pending: PendingItem[] }>;
export function executeDeploy(ctx: QueryContext, cert: LocalCert, plan: { report: DeployReport; pending: PendingItem[] }, defs?: ...): Promise<DeployReport>;
```

`PendingItem` 为 run.ts 内部类型（target + def + creds + service），两步拆开是为了终端模式下先出计划、确认后再执行。

- [ ] Step 1：测试（用假的 ProviderDef，不发 HTTP）：只纳入证书覆盖的域名；`-d` 精确匹配，点名但不覆盖 → failed `NotCovered`，点名但查无此域名 → failed `DomainNotFound`（该云/服务有查询 issue 时 message 提示「可能在查询失败的服务 xxx 上」）；没有 deployer 的服务 → skipped unsupported；sharedScope 组内有一条 not_due（未 force）或未被点名 → 全组 skipped `shared_cert_blocked`，message 点出挡住的域名；同组可更新时 apply 只调一次且 records 含全组；`certId()` 被多个服务调用时 uploadCertificate 只调一次；dryRun 不调用 apply / uploadCertificate，action 为 would_*；apply 抛 CloudApiError → failed 带 code / requestId / retryable；错误信息里出现私钥 PEM 正文时被替换为 `[私钥已隐藏]`；无 uploadCertificate 时 `certId()` 抛错并记为 failed。
- [ ] Step 2–4：失败 → 实现（执行时同一服务内 `mapLimit` 并发 3）→ 通过。
- [ ] Step 5：commit `feat(deploy): 部署编排与云服务部署接口`。

### Task 5–10: 各云 deployer（可并行，每家一个任务）

每个任务的文件只限 `src/providers/<p>/`（可新增 `deploy.ts` 等）与 `test/<p>-deploy.test.ts`，不改共享文件（README 说明写在任务报告里，由 Task 11 合入）。

每个任务的共同要求：
- 实现 `uploadCertificate`（上传到该云证书服务；先查重：同指纹 / 同序列号，或同 CN + 同到期时间；证书名 `sslbear-<CN 把 * 换成 _>-<到期 YYYYMMDD>`，超长按该云限制截断）。
- 为每个服务实现 `deployer`；能用证书服务 ID 绑定的优先用 `input.certId()`，只收 PEM 的直接传 `input.cert.certPem/keyPem`。
- `mode: "deploy"` 时同时开启 HTTPS；`update` 时只换证书。双证书服务只换同算法那张，保留另一张；查询层补 `certs` 与 `algorithm`（该服务支持双证书时）。
- 写接口里带 PEM 的请求不能放在 URL 上（如阿里云 RPC 需新增 POST 表单体调用）。
- 整体覆盖式接口先读后改。
- deployer 需要的定位信息（bucket、region、站点 ID、SubAppId、项目 ID 等）不在 `extra` 里时，在查询层补进 `extra`。
- mock 测试：每个服务至少覆盖 update、deploy（开启 HTTPS）的请求构造，以及上传查重命中 / 未命中。
- 写接口以官方 API 元数据为准（阿里云 api.aliyun.com/meta、腾讯云 tencentcloud-cli 的 api.json、火山 api.volcengine.com explorer、华为 support.huaweicloud.com 的 .md）；`../sslbear-e2e/setup/<p>-*.ts` 里有搭测试环境时绑定证书的写接口实现，可直接参考。
- 只跑自己的测试：`npx vitest run test/<p>-deploy.test.ts test/<p>.test.ts`；typecheck 只看自己目录的报错。
